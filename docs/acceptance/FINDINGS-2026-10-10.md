# Acceptance findings — 2026-10-10

Honest register from the v0.9.0 acceptance program: what works, what does
not, and what is fixed. Negative results are recorded as carefully as the
positive ones — an empty or stale answer is never "no risk".

Evidence lives in `target/tmp/acceptance-evidence/` (runner reports,
full agent transcripts, tool-traffic logs). Lanes: `onboarding.py` and
`contract_task.py`, `--mode graph` (scripted vs pre-declared ground truth)
and `--mode agent` (real coding agents, A/B with `--arm no-lain`).

## Fixed in v0.9.0 (each found by this program)

1. **`workspace_dir` contract mirrors were frozen** at their clone-time
   commit; no documented path (reindex / sync_state / request_reload /
   restart) moved them. Two bugs: `git fetch` without a mirror refspec
   never updated refs, and `resolve_ref` fetched only on missing refs
   (a stale branch tip never misses). Found by the `contract_task`
   canary "contract layer follows the committed change"; fixed in
   #285; the same canary now passes against the published binary.
2. **LSP install allowlist omitted `rustup` and `gem`** — the shipped
   recipes for rust-analyzer and solargraph were unconditionally
   refused. Found by the architecture health badge. **v0.8.0 as
   released is affected: upgrade to v0.9.0.**
3. **Homebrew formula checksums for v0.8.0 were wrong** (pre-filled
   from non-reproducible local builds) — brew installs failed
   verification since v0.8.0. Now filled post-publish from the
   published `SHA256SUMS`.
4. **Three release-process deadlocks** (documented in AGENTS.md):
   formula checksums must be filled post-publish; the health-badge
   default must bump post-publish (else the badge 404s and the
   release gate refuses to build); the tag must follow a green main
   CI run (the gate reads completed runs).

## Product gaps — Lain's data toward the agent

> **RESOLVED (all three) in the agent-facing-data PR** — see #292/#293/#294;
> the acceptance demo then flipped the AFFECTED-protocol streak 0/5 → broken.

5. **`Overlay freshness: stale` is printed while the persisted graph is
   current.** Misleads agents and harnesses: the v0.9.0 agent lane's
   agent reasoned around it ("an age marker on the live-edit overlay,
   since the persisted graph is current") and the harness marked the
   lane red on it. The marker must mean "answers may miss recent
   work", or say precisely what it is stale with respect to.
   **Priority: this is data Lain hands to agents.**
6. **Runtime scoping is not in the schemas.** `sync_state`,
   `get_job_status`, `get_contract` demand `repo_id` in multi-repo
   mode ("Config error: tool 'X' requires scoping: multiple repos")
   while `docs/tool-schema.json` declares the argument optional. An
   agent following the schema gets a config error.
7. **Lain cannot emit verifiable impact claims.** Across five real
   agent runs (v0.8.0 and v0.9.0, both arms), agents analysed impact
   correctly in prose/thinking — every consumer named, every decoy
   excluded — but zero `AFFECTED: <repo>:<file>:<symbol>  EVIDENCE:
   <class>` lines were emitted. The claims are not machine-checkable.
   The tool side should be able to produce the claim lines itself.

## Test flakes

> **RESOLVED**: #295 was a false oracle (git rename detection folded
> an identical-content delete+add into a rename the assertion could
> not see) — `--no-renames` + pinned seed + persisted regression
> seeds. #296 was torn mid-reindex answers — reader quiesce with a
> degraded banner, watcher-storm coalescing, and demo retries that
> keep the assertions strict. The #296 agent also surfaced the last
> silent negative (`run_sync`'s full-refresh lie), fixed in the same
> batch.

8. `server::git::verification::differential::sensor_agrees_with_git_after_every_operation`
   — proptest differential; failed 1 of ~9 full-battery rounds on an
   unrelated docs commit. Seed or budget needs pinning.
9. `scripts/demo.sh` — `find_anchors ranks the hub first` and
   `coupling radar sees the co-change` go non-deterministic under CPU
   contention (both failed while a full `cargo test --workspace` ran
   concurrently; both pass on an idle machine).

## Onboarding documentation gaps (found by an agent with no rescue)

10. README shows a hand-written `mcpServers` JSON; the real path
    (`lain setup --agent …`) is not in it.
11. `npm install -g` fails with EEXIST when an unrelated `lain` sits
    in `~/.local/bin`; `--prefix` is undocumented.
12. The lazy binary download (postinstall skipped → first run fetches)
    is undocumented.
13. `lain setup` registers the absolute cache-binary path, not `lain`
    as the README shows.
14. `lain setup` without `--agent`/`--lsp` is interactive on a TTY and
    silently defaults in non-interactive runs.

## What the program proved works (v0.9.0, real agents, published npm)

- Clean-room install from npm, docs-only onboarding, client config.
- Single-repo task: multi-file change, tests green, and a full
  convergence verification (`lain status`/`doctor`/`get_health` all
  agreeing on the indexed commit) before DONE.
- Multi-repo contract task: change across `orders` + `billing`, tests
  green in both, and **both** the symbol layer and the contract layer
  reflect the change — with the contract tools (`get_contract`,
  `trace_impact`, `list_unresolved`, `get_coverage`, …) called for
  real.
- The A/B does not separate on the small fixture (grep finds the same
  answers) — recorded so nobody over-claims; the differentiation needs
  scale and homonyms (the planned fixture).
