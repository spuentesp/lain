# Acceptance findings — 2026-10-11

Honest register from the A/B agent-utility program (the "¿para qué sirve
LAIN a un agente? realmente?" question). Seven-plus real agent runs across
three purpose-built fixtures, predeclared ground truths, and the same
discipline as the 2026-10-10 register: negative results are recorded as
carefully as positive ones. One experimental-contamination incident is
recorded in full below — it voided part of the series and the affected runs
were repeated clean.

Evidence lives in `target/tmp/acceptance-evidence/` (`ab-*`, `swarm*`,
`em-*`, `sc2-*`: runner reports, phase metrics, consensus artifacts,
transcripts, tool-traffic logs).

## The frame: an organizational code topology server

The program's outcome is a positioning decision as much as a set of
measurements. Lain is not one more MCP tool — a tool is skippable, and in
seven runs agents skipped it with grep and lost nothing at the finding
task. What survived every run is server-shaped:

- a **topology memory** of the organization's code — repos, services,
  contracts, couplings (static provenance and, since `anchor_miner`,
  heuristic edges mined from the same signals agents use),
- a **claims protocol** (`AFFECTED … EVIDENCE: …`) that turns analysis into
  machine-checkable artifacts,
- a **coordination substrate** (`claim_files`, presence, intents) that made
  multi-agent edits attributable and race-free in every run that had it.

MCP, the CLI and the Command Center are clients of that server. The
product is the topology.

## What was measured

Fixtures (all with ground truth declared before any agent ran):

| Fixture | Shape | Question |
|---|---|---|
| `scale_task` (6 repos) | field rename + indirect consumer + homonym/near-miss traps | does the graph beat grep at impact claims? |
| `swarm_deepchain` (7 repos) | 5-hop cross-language chain + out-of-workspace consumer | does the graph carry a swarm's consensus? |
| `enterprise_mesh` / `enterprise_scale` (10 → 80 repos) | gRPC + Kafka + AMQP + env-host coupling, 3 decoy traps, then 70 same-name noise repos | does the advantage appear where grep cannot join, and at scale? |

Arms: same model, same prompts, same commits — `--arm lain` vs
`--arm no-lain`; 3-agent runs used independent analysis (isolated copies) →
consensus/implementation (shared workspace) → cross-review.

## Verdicts

### 1. Finding the blast radius: careful agents + search matched the graph everywhere

Across every fixture and scale, individual agents reconstructing the blast
radius from code + config + named anchors matched or beat the tool-assisted
arm. The enterprise-scale run — 80 repos, 111 files carrying the renamed
field, coupling joinable only via `repos.yaml services[].env`, generated
gRPC stubs, topics and queues — ended with 5/6 individuals at full recall
in BOTH arms and both consensuses perfect. Agents do not grep the field
name; they grep the contract's structural names (proto, topic, queue,
route), which collapses the search space. Decoy volume punished nothing:
zero decoy claims were made in the clean scale run.

**Consequence:** we do not claim a discovery advantage over human+search
at the tested scales (≤80 small repos). The only coupling class where the
graph should win outright — no named anchor anywhere in the workspace — is
today the class where the graph is also blind.

### 2. Certification and coordination: the graph's real, repeatable advantage

- The `AFFECTED` protocol survived into group artifacts in every LAIN run
  (scoreable, complete, classes correct) and repeatedly failed in control
  runs (consensus written as prose — semantically rich, machine-unverifiable
  — or with claims left unresolved).
- `claim_files` produced attributable, race-free divisions in every run
  that had it. Control swarms raced commits (one agent committed another's
  work) or hoarded them.
- The LAIN swarms' consensus never erred across the series; control
  consensuses inherited individual overclaims at least once.
- Post-change `INDEX-CHECK` with commit-pinned provenance is something
  grep cannot emit.

### 3. Cost

Token parity (~45K output per arm). Wall time +15–30% with Lain (tool
turns). The old 4× premium was a harness artifact (single-agent A/B with
heavy sync behavior), not a property of the tool.

## Contamination incident (voided runs)

The `role:` column of every fixture's `repos.yaml` copied the ground-truth
descriptions — `"CLASS A (env-host) — calls orders-svc's route via
os.environ['FIN_ORDERS_BASE']…"`, `"DEEP consumer — reads via dynamic
key…"`, `"NOISE — zero coupling…"`. Every agent reads `repos.yaml` first:
the analysis was handed over in the manifest. All "finding" conclusions
from the runs before 2026-10-11 are void (they are kept as evidence, not
as results). Fixed in `877fb7bc` (neutral service-catalog roles in all
three fixtures, hostile-grep audit clean) and the decisive scale run was
repeated clean (`sc2-*`) — whose results are the ones quoted above.

## Product gaps found by this program (and fixed)

1. **Federation roots were second-class** — `lain setup`/`mcp`/`impact`/
   `doctor` demanded a `.git` clone and never mentioned `repos.yaml`, so
   agents in a multi-repo workspace never found `lain server --config
   ./repos.yaml` (36 futile `lain mcp` restarts observed). Fixed in
   `c6b2a070`: setup writes the federation entry, errors name the fix.
2. **Three sensor gaps made designed coupling invisible** —
   `confluent_kafka.subscribe([])` produced no topic edge; Java
   `System.getenv("X") + path` never reached host resolution; gRPC env
   dial targets landed `RpcStubUnknown`. Fixed in `e1b3008e` (all three
   now bind or land `env_unmapped` naming the var).
3. **Harness bugs (ours, not the product's)** — a Python traffic shim that
   aborted at interpreter shutdown (agents saw fake crashes), `package_dev`
   shipping a stale binary when `target/release` was warm, and a claims
   scorer that dropped claims phrased with field-sites/spaces and counted
   free-text known-unknowns as decoys. All fixed and regression-pinned
   (`1c08be02`, `6d419807`, `ee4e83ad`, `d467d24b`).

## The response: heuristic edge-minting (`085c18f3`)

The winning agent strategy — structural name anchors, co-change, commit
references — is now a graph input. `anchor_miner` mints heuristic edges at
federated index build: `anchor:queue|topic|route|proto|env` at 0.6,
`cochange`/`commit-ref` at 0.3, detector named on every edge, claims
therefore `needs-investigation`, never `verified`. Field-name anchors are
structurally impossible; crowds (>8 repos) are skipped; static edges win.

Smoke on the 80-repo fixture: 50 anchors → 162 anchor + 21 co-change edges
in 8s. The AMQP consumer that had zero facts (`ledger-svc`) is now
reachable (`anchor:queue:order-events`); the unbound HTTP consumer
(`fraud-check`) via `anchor:route:/v1/orders`; traps and 70 noise repos
receive nothing; the static binding stays `Static/1.0`. The graph now
learns what the experiments proved works — and the acceptance fixtures are
its regression suite.

## Open items

- **Runtime-only coupling** (service mesh DNS, external registries,
  generated clients from private packages): the remaining discovery
  advantage class, and still invisible to both the static sensors and the
  anchor miner. The class-C blind spot is documented, not solved.
- **Scale beyond the tested band** (500+ repos, or anchors buried in
  generated/vendored code): untested; the verdict is bounded by n≈1–2 per
  configuration and by ≤80-repo workspaces.
- **README/positioning reframe** to the topology-server frame above — the
  naming work starts here, the product copy follows.
