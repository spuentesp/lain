## Findings, ordered by priority

### 1. P1 — Windows tests no longer compile after lint cleanup

Location: `tests/use_cases/battery_success_metrics.rs:505`.

The binary path is declared with `let lain`, but the Windows-only block calls `lain.set_extension("exe")`, which requires a mutable binding. The Linux cleanup removed mutability needed on another target.

Evidence: [CI run 34655064677](https://github.com/spuentesp/lain/actions/runs/34655064677) fails with E0596 at line 508 on Windows. The failing code remains at the reviewed HEAD; this was not merely a network or runner failure. That run tested `49d6306`, not the later local HEAD.

Fix: construct the platform-specific filename without mutation, or retain an appropriately scoped mutable binding. Verify with Windows test compilation.

### 2. P1 — Overlay refresh removes live symbols from sidecars

Location: `src/server/ingest/ingestion.rs:570` and `:582`.

`sync_volatile_overlay` removes old owner entries, calls `process_change` (which broadcasts replacement inserts), then broadcasts all old IDs as removals. A symbol whose name/path/location remains unchanged gets the same ID on each refresh. The sidecar therefore receives `add(id)` followed by `remove(id)`, while the owner retains the replacement.

Reproduction: create one uncommitted Rust function, subscribe to the broadcast bus, synchronize twice, and apply emitted diffs in order. **Owner: 1 node; sidecar: 0 nodes.** This does not require concurrent calls or an LSP.

Fix: publish removals before replacements, or publish a coherent diff whose application order preserves surviving IDs. Add a repeated-refresh test comparing owner and subscriber state.

### 3. P1 — The concurrency mutex is never acquired

Location: `src/server/ingest/ingestion.rs:605`; declaration in `src/server/ingest/server.rs:91`.

`process_change_lock` is a Tokio mutex, but the code assigns `self.process_change_lock.lock()` without `.await`. That creates an unpolled future, not a guard. The advertised serialization fix has no effect.

The existing concurrency test writes the same symbol through both calls and checks that one ID remains. Idempotent insertion satisfies that assertion even without serialization. Also, cleanup and the changes snapshot in `sync_volatile_overlay` sit outside this mutex, so merely awaiting the existing lock does not serialize the entire reconciliation operation.

Fix: acquire an async guard and define a lock boundary covering snapshot, removals, replacement, and bookkeeping without recursive locking. Test distinguishable overlapping edits and reconciliation calls.

### 4. P2 — Deleting the last tracked file leaves permanent graph ghosts

Location: `src/server/ingest/ingestion.rs:755`.

`sweep_orphans` skips pruning when Git successfully returns an empty tracked-file set. Both ingestion pipelines call it for deletion-only commits and then advance the indexed commit. An empty repository is a valid result; treating it as a failed scan strands the old nodes and allows future commit-based passes to short-circuit.

Reproduction: index a repository containing only `lib.rs` and `original()`, commit deletion of `lib.rs`, and index again. **Both `lib.rs` and `original` remain.**

Fix: distinguish an error listing tracked files from a successful empty result, and prune all obsolete nodes for the latter. Cover both single-repository and federation pipelines.

### 5. P2 — Removing a repository leaves its projected graph queryable

Location: `src/server/federation/federated_index.rs:227`.

`remove_repo` updates membership, rebuilds the symbol index, and saves the manifest, but never removes that repository's nodes or incident edges from the shared backend. Backend-based search and workspace views can retain results from a removed repository.

Reproduction: add and index a one-function repository, project it, then remove it. **Membership is removed, but the backend still contains two nodes.**

Fix: retract the repository's projected nodes and related edges, and reconcile its owned overlay state and watcher lifecycle. Check membership and query results after removal, not only the manifest.

### 6. P2 — The namespace regression test panics on its intended path

Location: `tests/watcher_freshness.rs:1192`.

`Arc::get_mut(&mut Arc::clone(&server)).unwrap()` cannot succeed while the original `server` Arc remains alive. The test returns early when `rust-analyzer` is found, which hides the panic in this environment's normal suite.

Reproduction: execute `overlay_and_static_have_matching_ids_for_same_symbol_no_lsp` with `PATH=/usr/bin:/bin`. **It panics at line 1193 before asserting static/overlay ID equality.**

Fix: call `server.sync_volatile_overlay()` directly; it already takes `&self`. Make LSP availability controllable in the fixture so the intended fallback check always executes.

### 7. P2 — Badge threshold and language inputs do not reach the script

Location: `.github/actions/lain-health-badge/action.yml:69`; script consumers at `health.sh:17` and `:146`.

`health.sh` reads `INPUT_MIN_FAN_OUT` and `INPUT_LSP_LANGUAGES`, but its composite step exports neither. Thus callers' `min-fan-out` and `lsp-languages` settings are ignored, normally falling back to `15` and `auto`. GitHub does not automatically populate `INPUT_*` variables for composite actions. [GitHub metadata reference](https://docs.github.com/en/actions/reference/workflows-and-actions/metadata-syntax#inputs)

There is a second empty-value problem: `${INPUT_LSP_LANGUAGES:-auto}` treats an explicit empty string as `auto`, contradicting the documented option to disable LSP installation with an empty input.

Fix: explicitly map the inputs into the step environment and preserve an intentional empty language value. Verify a custom threshold and disabled LSP installation.

### 8. P2 — The badge's version pin selects the installer, not the binary

Location: `.github/actions/lain-health-badge/action.yml:61`; `install.sh:221` and `:427`.

`lain-version` selects the Git revision from which to download `install.sh`. That script independently queries `/releases/latest` and installs that result. Selecting an older release therefore does not pin the binary, and a subsequent release changes the executable used by an unchanged workflow.

Fix: pass a supported explicit binary version to the installer, or download the selected release asset directly. Test with a requested version different from the mocked latest release.
