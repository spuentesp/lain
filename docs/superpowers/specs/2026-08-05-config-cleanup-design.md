# Config Cleanup — Design

**Date:** 2026-08-05
**Status:** Approved (pending implementation)
**Branch:** `claude/ieee-830-srs-spec-m3ajim`

## Goal

Remove dead/orphaned config artifacts and fix version drift across the LAIN repo. Leave load-bearing config (hooks, install scripts, workflows, `.claude/` user settings) untouched.

## Scope

In scope:
- One tracked placeholder file that should not exist
- Version drift between `Cargo.toml` (source of truth at `0.3.0`) and two derived manifests
- Untracked build artifacts in `docs/srs/final/`
- One untracked stray PDF at the repo root
- Three new `.gitignore` patterns to prevent regressions

Out of scope:
- `.claude/settings.local.json` — already gitignored, user-local, not a leak
- `hooks/{claude,cline,cursor,windsurf}/` — load-bearing, referenced by `src/cmds/hook.rs`, `tests/e2e-sandboxed.sh`, `scripts/pre-flight-check.sh`
- Untracked SRS work-in-progress files (`SRS-final.md`, `SRS-LAIN-IEEE830.pdf`, `anexos/G-estado-real-lain.md`) — could be intentional; not touching without explicit decision
- Tracked HTML files in `docs/srs/presentacion/` — render artifacts that are intentionally committed
- Pre-existing uncommitted modifications to `docs/srs/*` — separate work in progress

## Changes

### 1. Delete tracked file

| Path | Reason |
|---|---|
| `toolchains/zig` | 10-byte file containing literal text `build.zig`. Not a real toolchain profile. The README in the same dir implies `.toml` files; this entry does not fit the pattern. |

### 2. Delete untracked files / directories

| Path | Reason |
|---|---|
| `docs/srs/final/` | Entire untracked directory: `build.py`, `cdp_print.py`, `__pycache__/`, `*.svg`, `_doc.html`, `_render.html`. Local build output of the SRS HTML pipeline. |
| `docs/SRS - DataPort - Gabriel Aillapán.docx (1) (3) (1).pdf` | Untracked file at repo root. Filename contains `(1) (3) (1)` rename markers — appears to be a stray. Unrelated to LAIN. |

### 3. Edit tracked files for version consistency

Source of truth: `Cargo.toml` `version = "0.3.0"` (recent commit `91fd7c6 chore: bump version to 0.3.0`).

| File | Line | Change |
|---|---|---|
| `server.json` | 5 | `"version": "0.2.0"` → `"version": "0.3.0"` |
| `server.json` | 36 | `"version": "0.2.0"` → `"version": "0.3.0"` (inside the `packages` array) |
| `npm-shim/package.json` | 3 | `"version": "0.2.0"` → `"version": "0.3.0"` |

`Formula/lain.rb` already at `0.3.0` — no change.

Note: `scripts/pre-flight-check.sh` already enforces version consistency between `Cargo.toml`, `server.json`, and `README.md`. The npm-shim `package.json` is not currently covered by that check, which is why it drifted.

### 4. Update `.gitignore`

Append three patterns, placed next to the existing Python cache block (`.mypy_cache/`, `.pytest_cache/`):

```
# Python build artifacts
__pycache__/
*.pyc

# Underscore-prefixed intermediate render outputs (matches docs/srs/final/_*.html)
_*.html
```

These do not conflict with tracked files:
- `docs/srs/presentacion/img/*.html` and `presentacion.html` — none match `_*.html`
- `__pycache__/` is not present in tracked files
- `*.pyc` is not present in tracked files

## Verification

After changes:
1. `git ls-files toolchains/` — should show only `toolchains/README.md`
2. `grep -n '"0\.2\.0"' server.json npm-shim/package.json` — should produce no output
3. `grep -c '^version' server.json npm-shim/package.json Formula/lain.rb Cargo.toml` — should each return 1
4. `git ls-files docs/srs/final/` — should produce no output, and the working tree should not contain the directory
5. `test ! -f 'docs/SRS - DataPort - Gabriel Aillapán.docx (1) (3) (1).pdf'` — should succeed
6. `git check-ignore -v docs/srs/final/__pycache__/foo.pyc docs/srs/final/_doc.html` — should report matches
7. `cargo build` — should succeed (sanity)
8. `scripts/pre-flight-check.sh` — should pass (verifies version consistency among Cargo.toml, server.json, README)

## Risks

- **None for tracked files.** `toolchains/zig` is never referenced by code (verified via grep against `src/` and `scripts/`). Version bumps are aligned with the source of truth.
- **Low for untracked deletions.** The user can restore from trash if needed. The `docs/srs/final/` artifacts can be regenerated by re-running `build.py` in that dir.
